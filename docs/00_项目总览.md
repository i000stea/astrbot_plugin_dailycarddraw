# 项目总览

## 项目目标

在当前项目中实现一个面向 QQ 号管理的 AstrBot 每日抽卡插件，并补齐云端后端接口与 MySQL 持久化能力。

插件的核心目标不是单纯返回“随机结果”，而是形成一套可扩展的抽卡系统基础设施，至少覆盖：

- 每个 QQ 号可按自然日参与抽卡
- 支持单抽、十连、后续活动池扩展
- 支持今日结果查询、历史记录查询、累计统计
- 支持管理员维护卡池、卡牌、权重与开关状态
- 插件侧与云端侧职责清晰分离

## 参考来源

当前项目已经复制参考插件 `astrbot_plugin_debounce` 的基础骨架文件，用于保留标准 AstrBot 插件项目结构。

参考的价值主要在于：

- 复用标准插件目录结构
- 复用 `main.py` 的插件入口写法
- 复用 `metadata.yaml`、`_conf_schema.json`、`requirements.txt` 的基本位置约定

不复用的部分：

- 消息防抖业务逻辑
- BERT 模型依赖
- 原有 README 的业务描述

## 当前确认的产品方向

### 已确认

- 抽卡模式走多模式路线，第一版即考虑：
  - 单抽
  - 十连
  - 不同卡池入口的可扩展设计
- 抽卡数据按 `QQ 全局` 统计
  - 同一个 QQ 在不同群中共享同一份每日抽卡状态
- 云端后端走 `MySQL API`
  - AstrBot 插件不直接连云数据库
  - 插件通过 HTTP API 调用后端服务
- 第一版包含：
  - 用户抽卡
  - 今日结果
  - 历史记录
  - 累计统计
  - 管理员卡池维护能力

### 暂未锁定

- 十连是否带保底
- 每日单抽与十连的次数关系
- 管理端命令是纯文本命令，还是需要兼容更复杂的管理参数格式

## 第一版建议定位

建议第一版优先落成“可运行的抽卡底座”，而不是一开始就把全部活动玩法做满。

推荐第一版完成：

- 基础卡池配置
- 单抽与十连
- 每日次数控制
- 云端落库
- 个人记录查询
- 累计统计
- 管理员增删改查

第二阶段再考虑：

- 保底机制
- UP 池
- 卡牌图鉴
- 群专属活动池
- 稀有度播报模板定制

## 交付形态

本项目后续建议同时产出两部分：

1. AstrBot 插件
   - 负责命令接入、参数解析、权限判断、响应格式化
2. 云端后端服务
   - 负责业务规则校验、数据库写入、统计汇总、管理 API

这样可以避免把数据库访问和复杂业务逻辑全部堆入插件入口文件中。
